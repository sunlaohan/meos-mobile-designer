# MEOS Mobile Designer

基于 Vue 3、TypeScript 和 `persagy-vant` 的 Web 可视化移动端页面设计平台，界面名称为 **Meri Mobile Designer**。支持拖拽搭建、图层与属性编辑、AI 生成、真实组件交互预览，以及 Vue 单文件组件、设计 JSON 和中文组件说明导出，适用于巡检、工单、表单和详情等移动业务页面的原型与开发交付。

组件缩略图、画布和预览均使用真实组件，属性面板来自组件中文 README 的公开 API；AI 生成读取组件库配套的 `use-persagy-vant` Skill 与组件文档。当前本地验证使用 `persagy-vant 0.0.51`，实际版本以链接的组件包为准。

## 技术栈

| 部分 | 技术 |
| --- | --- |
| 编辑器 | Vue 3.2.38、TypeScript 5、Vite 5 |
| 移动端组件 | `persagy-vant`，通过本地源码链接接入 |
| 图标 | `lucide-vue-next` 与组件库内置图标 |
| AI 接口 | Node.js + Vite 服务端插件，调用 OpenAI 兼容网关 |
| 数据与导出 | 浏览器 `localStorage`、JSON、Vue SFC、Markdown |
| 自动化验证 | Node.js 内置测试运行器、`vue-tsc` |

## 快速开始

### 1. 准备环境和组件库

- Node.js 20 或更高版本；当前验证环境为 Node.js 20.20.0。
- pnpm 10.33.0，与 `package.json` 的 `packageManager` 一致。
- 可用的 `persagy-vant` 组件库源码，包含构建产物及配套 Skill。组件库需按自身说明完成依赖安装和构建。

**本仓库不包含组件库源码，当前也不是仅安装 npm 组件包即可独立运行的项目。** 元数据生成会读取以下组件包内容，请使用有访问权限的组件库完整工作区：

```text
persagy-vant/packages/persagy-mobile/
├── package.json
├── vant.config.mjs
├── src/                         # 各组件 README.zh-CN.md、示例、类型和样式变量
├── es/                          # ESM 构建产物，包含 icon/gif.mjs
├── lib/                         # 组件构建产物及 index.css
└── skills/use-persagy-vant/      # SKILL.md 与 references/
```

### 2. 克隆仓库并检查本地路径

```bash
git clone https://github.com/sunlaohan/meos-mobile-designer.git
cd meos-mobile-designer
```

当前代码沿用开发机目录配置：

| 配置位置 | 当前值 | 在其他电脑运行时的调整 |
| --- | --- | --- |
| `package.json` → `dependencies.persagy-vant` | `link:/Users/sunlei/Component/persagy-vant/packages/persagy-mobile` | 改为实际组件包目录的 `link:` 路径 |
| `scripts/generate-component-metadata.mjs` → `componentRoot` | `/Users/sunlei/Component/persagy-vant/packages/persagy-mobile/src` | 改为实际组件包的 `src` 目录 |
| `vite.config.ts` → `server.fs.allow` | `/Users/sunlei/project/meos-mobile-designer`、`/Users/sunlei/Component/persagy-vant` | 改为本项目与组件库的实际目录 |

修改路径后执行 `pnpm install`，同步更新锁文件。开发机路径一致时可直接使用现有配置。需要重新链接组件包时，也可执行 `pnpm add "persagy-vant@link:/实际路径/persagy-vant/packages/persagy-mobile"`。

### 3. 安装并启动

```bash
pnpm install
pnpm dev
```

打开 [http://localhost:4173/](http://localhost:4173/)。`pnpm dev` 会先生成组件属性、分类、图标、设计变量与 AI 组件目录，再启动编辑器；端口被占用时以终端输出的地址为准。

未配置模型密钥时，可以使用首次打开的示例画板、拖拽编辑、预览、保存和导出；AI 模型列表与页面生成需要完成下一步配置。

### 4. 配置 AI 页面生成（可选）

首次配置时复制示例文件；已有 `.env.local` 时直接编辑，保留原配置：

```bash
cp .env.example .env.local
```

在 `.env.local` 中填写：

```dotenv
DESIGNER_LLM_BASE_URL=https://sandbox.meos.center/bill-token-server/v1
DESIGNER_LLM_API_KEY=填写你有权限使用的网关密钥
DESIGNER_LLM_DEFAULT_MODEL=gemini-3.8-flash
```

| 变量 | 说明 |
| --- | --- |
| `DESIGNER_LLM_BASE_URL` | 提供 `/models` 与 `/chat/completions` 的兼容网关地址；默认使用项目现有公司网关 |
| `DESIGNER_LLM_API_KEY` | 服务端模型密钥，启用 AI 功能时必填 |
| `DESIGNER_LLM_DEFAULT_MODEL` | 默认模型 ID；需由网关提供，并符合 `server/ai-core.mjs` 的型号白名单 |

保存后重启开发或预览服务。密钥只由 Node 服务读取，不使用 `VITE_` 前缀；`.env.local` 已加入 Git 忽略规则。浏览器调用同源 `/api/ai/models` 和 `/api/ai/generate`，不会接收密钥。自行更换网关时，还需检查型号白名单与图片输入兼容性。

## 基本使用

1. 从左侧组件库搜索组件，点击或拖入手机画布；也可选择模型并描述页面需求，生成可编辑草稿。
2. 在画布或图层树中选中组件，在右侧修改公开属性、数据、布局和设计变量。
3. 将同层组件编组为容器，调整层级与间距；为按钮、字段或操作栏配置打开面板的交互。
4. 点击「预览」在新窗口操作真实组件，检查弹层、选择器和容器扩展。
5. 点击「保存」将当前设计写入本浏览器；从右下角「导出」选择 Vue、JSON 或组件说明文档。

例如可输入：「生成巡检任务列表页，包含导航栏、搜索、状态筛选、工单卡片和底部操作栏，点击筛选打开筛选面板。」生成后仍需检查示例数据、组件选型和构建说明。

- 单个组件、已有容器或同一层级的多个图层均可创建父级容器，支持多层嵌套、容器属性编辑与解组

- 新窗口交互预览
- 动作栏固定在手机底部；弹出面板不占页面流，选中面板图层可临时预览，保持文档默认收起状态
- 固定导航栏在模拟状态栏下方独立显示，滚动时保持可见；启用「占位」时在原图层位置保留导航栏高度，编辑、缩放和交互预览一致，导出保留原始公开属性
- 单元格、按钮、输入框、导航栏、动作栏及工单操作支持右侧「交互」配置：选择已有面板，或从组件库拖入 / 新建并关联；支持更换、解除关联和撤销
- Vue SFC、设计 JSON、组件说明 Markdown 三种导出格式

## 树选择与批量多选

树选择和批量多选在资源面板中展示真实组件缩略图，拖入即带示例数据。在画布中点击组件后，右侧可以修改数据；到「预览」中操作选择、展开与收起。

- 树选择：「树节点」使用 `[{"id":"group","text":"设备分类","children":[{"id":"air","text":"暖通空调"}]}]`；「选中节点」和「展开节点」分别是节点 id 数组。打开「多选」后可选多个末级节点；父级是否可选和父子联动由对应开关控制。
- 批量多选：「选项列表」使用 `[{"name":"巡检工具"},{"name":"安全用品"}]`；「勾选状态」与选项顺序一致，例如 `[1,0]` 表示只选第一项。预览中可以勾选、展开已选、移除或清空；确认会显示当前选中项数。

示例数据、选中状态、树节点展开状态和批量多选展开状态均保留在设计 JSON 中，Vue 导出包含相应的双向绑定。

## 交互关联

选中触发组件，在右侧「交互」选择触发时机，点击虚线框选择关联控件。列表按选择控件、内容与业务面板、弹层与反馈、媒体预览分组，完整展示 25 种独立支持显示控制的控件，包括多选/树选择面板、单人/多人/对象选择、物料面板、日历、数字键盘、弹出框、动作/分享面板、气泡、提示、图片/视频预览等，也可搜索并复用画板已有实例。支持范围由 shared/association-controls.mjs 统一定义，并与已安装组件的公开 show 接口做覆盖校验；普通标签和行内楼层选择不作为独立弹层。选择控件类型或从左侧组件库拖入，会创建默认收起的新控件；从图层拖入会关联已有实例，不改变图层位置。关联控件直接在虚线框内回显，右侧删除按钮与控件信息居中对齐，点击卡片更换或拖入替换；点击编辑图标会在模拟器中打开关联控件，并切换右侧属性。模拟器和属性面板均提供「退出编辑」，退出后返回原触发组件；编辑状态不写入组件的 show 属性，属性修改正常保留；不支持的控件显示错误并保留原关联。关联关系保存在设计 JSON 中，Vue 导出使用事件和 `v-model:show`，交互预览中点击入口即可打开、关闭真实面板。选择器的业务数据与选中结果回填规则仍由业务工程接入。

更换关联会保留原面板；点击关联卡片的删除按钮，会同步删除对应面板图层及其子图层，并清理指向这些图层的所有关联，撤销可一并恢复。

## 容器扩展

选中分组或背景，在右侧「容器扩展 → 添加扩展」中选择下拉刷新（PullRefresh）、触底加载（List）、懒加载（Lazyload）、吸顶／吸底（Sticky）。支持组合、启停、参数设置、移除及撤销；图层面板回显已启用的能力，配置随本地保存和 JSON 保留，不新增或移动子图层。父子容器不允许重复启用同类能力，也会检查已有原生包装组件和跨组拖动。

编辑时完整显示内容，不执行手势或延迟渲染。预览复用真实组件，下拉刷新支持触摸及桌面鼠标向下拖动；触底加载演示一次完成，刷新后可再次加载。不会发送业务请求或伪造新增数据。懒加载使用原生 LazyComponent，按手机滚动视口决定挂载时机，支持占位高度；Sticky 的预览位置按手机可视区适配。

Vue 单文件导出内置同一运行时及所需依赖，自动注册懒加载。业务工程在导出文件的 `containerDataHandlers` 中按容器 ID 提供 `refresh` / `load` 异步处理器，更新页面数据后返回 `{ finished: boolean }`；未配置处理器时安全结束，异常显示加载失败重试。JSON 保留启停状态及全部参数，Markdown 包含扩展清单。侧滑操作、折叠面板暂未纳入本期扩展。

## 组件元数据同步

`pnpm dev` 和 `pnpm build` 会先执行 `scripts/generate-component-metadata.mjs`，从本机 `persagy-vant` 的中文 README 重新生成属性元数据。因此组件库新增或修改公开 Props 后，设计器无需手动维护第二份 API 表。

同一脚本还会从组件库实际加载的 `lib/index.css` 同步规范变量，并结合公共变量声明区分公共规范与组件变量。属性选择后保存 `var(--van-*)` 引用，画布、交互预览、设计 JSON 和 Vue 导出均保留引用。参与组件内部数值运算的属性保留原有输入方式。

## 组件 Skill 与初始示例

模型直接读取当前安装包的 `SKILL.md`、页面配方、设计交互基线、复用规则、变体选型和动态面板规范，并结合组件的真实文档生成设计草稿。界面不再提供页面配方、页面状态、手填标题或本地规则模式；只保留模型选择与需求描述。模型不可用或返回无效数据时直接报错并保留当前画板。

页面标题由模型根据描述提炼；用户在描述里明确指定名称时遵循该名称。服务端以规划标题为准同步导航栏 `title` 与设计文档标题，避免分阶段生成的标题不一致。生成结果的标题和组件一起进入历史记录，撤销/恢复时一并回显。

构建结果支持真实组件默认插槽、图层编辑、面板入口与 Vue 导出。构建说明记录 Skill 版本、文档指纹、元素-组件匹配、变体、公开属性和未接入项；保存、JSON 及 Markdown 导出包含该记录。手动修改画布后清除旧构建记录，撤销可恢复对应记录，防止旧检查结果被当成当前页面的验收结果。

输出为使用示例数据的设计草稿。业务数据、搜索筛选、分页刷新、上传服务、提交校验与接口回调仍需业务工程接入。组件结构覆盖率只计算组件与纯布局的构成，不等同于业务流程已验收。内部的本地配方函数仅用于首次打开时的默认示例和开发校验，不作为模型失败后的替代生成结果。

## 模型生成

复制 `.env.example` 为 `.env.local`，填写服务端 `DESIGNER_LLM_API_KEY`，然后运行 `pnpm dev`。已有本地配置可直接使用。`DESIGNER_LLM_BASE_URL` 默认指向公司网关，`DESIGNER_LLM_DEFAULT_MODEL` 默认为 `gemini-3.8-flash`。密钥没有 `VITE_` 前缀，受 `.gitignore` 排除，仅由 Node 服务读取；浏览器只请求同源 `/api/ai/models` 和 `/api/ai/generate`，不接收密钥。

模型列表从网关 `/models` 获取并缓存 5 分钟，再按 `server/ai-core.mjs` 的固定选型表每家保留一个型号。当前白名单涵盖 Google、DeepSeek、阿里、OpenAI、Anthropic、智谱、月之暗面、腾讯、MiniMax 和小米；具体模型 ID 以代码为准。该列表是项目内的适配配置，不代表模型服务商的最新型号、价格排序或当前密钥的调用权限。

可手动刷新型号列表；只返回网关当前仍提供的已审查型号，不把新增/未知型号自动加入下拉框。默认仍为 Gemini，原先记住的型号若已移除会回到默认。网关列出的型号不代表当前密钥一定有权限，401/403/429 和超时会明确提示；不会自动改用其他模型或离线结果。生成中可取消，失败保留原画板，成功结果可以撤销。生成过程中修改画板会阻止迟到结果覆盖当前内容。

每次生成分两次模型调用：先读取真实 Skill 和组件目录盘点元素、选择组件，再读取所选组件的完整 README、可用 demo、类型与样式变量文档，生成页面 JSON。服务端按设计器实际组件目录校验属性、布尔/数值/枚举类型、默认插槽、节点标识和面板目标，并拒绝 HTML/脚本、原型污染、通用弹层与组件样式覆盖。最多 100 个节点、10 层嵌套。模型可产生设计或语义偏差，自动结构检查并非完整 Skill/业务验收；需检查构建说明中的示例数据、能力缺口和配置占位提示。

涉及组件交互时，规划阶段同时列出具体入口、事件和目标实例。生成后服务端按稳定节点 ID 补齐 `actions`，同类字段和面板分别绑定；支持的事件与手动交互编辑器共用清单，包括字段/按钮点击、导航栏左右操作、动作栏主/次/图标/更多操作、工单操作。弹出控件默认收起，并校验从页面到嵌套面板的入口可达性，拒绝无入口面板、失效目标和组件不支持的事件。交互缺失时使用同一模型和已读取文档自动修正一次；仍不完整则报错并保留原画板，不以「交互待接入」替代可实现的绑定。生成摘要、构建报告及导出会保留实际关系；数据查询、提交接口、选择结果回填与业务校验仍需接入。

`pnpm generate:metadata` 同步服务端组件目录。`pnpm preview` 同样注册模型接口；直接静态托管 `dist` 不包含 Node 服务，需要另行部署或反向代理这些接口。对外部署时应给模型接口添加现有公司的登录权限和用量限制。

## 图片与代码附件

生成区的「图片」「代码」按钮可多选文件，也可将文件拖入生成区。在需求输入框中粘贴剪贴板图片会添加为附件，普通文本粘贴保持原样。图片可点击缩略图放大，代码可展开查看，右侧叉号可移除。可以只添加附件、不填写文字，由模型分析后生成标题与页面。生成失败或取消时保留附件供重试。

支持 PNG/JPG/WebP，单张不超过 5MB、最多 4 张；代码/文本支持 Vue、JS/TS、HTML/CSS、JSON、Markdown、Python 等 UTF-8 文件，单份不超过 100KB、合计不超过 200KB。最多 6 个附件，总大小不超过 12MB。前后端共用类型、字节数、文件数量与图片签名校验规则；服务端请求体上限为 18MB，按 Buffer 拼接后一次解码 UTF-8，避免中文在分块边界损坏。

只有点击生成才会把附件随请求发送到公司模型网关。图片通过 OpenAI 兼容的 `image_url` Data URL 传入，代码以参考文本传入两阶段上下文，不执行附件代码，也不遵循附件内的指令。当前已接入 Gemini、Qwen 3.5+、GPT、Claude、Kimi 的图片输入；其他路线使用文本/代码，添加图片时会明确提示切换型号或移除图片，不会静默忽略图片。实际兼容性与权限仍以网关返回为准。

附件仅在当前生成区内存中保留，不写入服务端文件系统或设计文档；构建报告只记录文件名、类型与大小，不保存截图或源代码。参考截图不能替代真实组件页面，生成结果仍经过原有组件和属性校验。

## 导出与业务接入

| 格式 | 内容及用途 |
| --- | --- |
| Vue 单文件组件（`.vue`） | 保留真实组件、嵌套布局、双向绑定、面板交互和容器扩展运行时，供使用兼容版本 `persagy-vant` 的 Vue 3 业务工程接入 |
| 设计 JSON（`.json`） | 保存页面标题、节点树、属性、交互、容器扩展与生成报告，用于设计数据归档或后续系统接入 |
| 组件说明（`.md`） | 输出页面结构、组件复用清单、设计规范、容器扩展与 AI 构建说明 |

业务工程仍需接入查询、分页、上传、提交、校验、选择结果回填等逻辑。容器刷新和加载的接入位置为导出文件中的 `containerDataHandlers`。当前界面提供 JSON 导出，尚未提供通用 JSON 文件导入入口。

## 部署与当前边界

- `pnpm build` 产物位于 `dist/`。仅静态托管时可提供编辑器页面，AI 功能还需独立 Node 服务或反向代理；当前仓库的 AI 接口集成于 Vite 开发及预览服务中，`pnpm preview` 用于本地验证。
- 对外部署模型接口时，需要接入公司的登录权限和用量限制；当前中间件包含同源检查、附件校验和生成并发限制，尚未接入账户系统。
- 当前保存使用本浏览器、本源站的 `localStorage`，不同端口、域名或设备不会自动同步；清理浏览器数据会移除已保存设计。云端保存、版本历史与多人协作需要另行开发。
- AI 输出为使用示例数据的可编辑草稿，结构校验和组件覆盖率不等同于业务流程验收。模型不可用、无权限或结果无效时会报错并保留当前画板。
- 组件库和 Skill 是外部依赖，升级后需重新生成元数据，并运行 `pnpm build` 与 `pnpm test` 检查兼容性。

## 常见问题

| 问题 | 排查方式 |
| --- | --- |
| 安装时找不到 `persagy-vant` | 检查 `package.json` 的 `link:` 路径，并确认组件库完整工作区已准备好 |
| 生成元数据时报 `ENOENT` | 检查 `componentRoot`、组件 README、`vant.config.mjs`、`lib/index.css`、`es/icon/gif.mjs` 和 Skill 文件 |
| Vite 拒绝访问组件库文件 | 将本项目和组件库实际目录加入 `vite.config.ts` 的 `server.fs.allow` |
| 模型提示尚未配置密钥 | 检查 `.env.local` 的 `DESIGNER_LLM_API_KEY`，修改后重启服务 |
| 模型列表为空或调用失败 | 检查网关地址、网络、密钥权限及 `server/ai-core.mjs` 中的型号白名单；401/403/429 会在界面明确提示 |
| 图片附件无法生成 | 切换到当前适配图片输入且有调用权限的模型，或移除图片；文本和代码附件可继续使用 |
| 4173 端口被占用 | 检查是否已启动 macOS 常驻服务，使用 `pnpm service:status` 查询状态 |
| 导出后的页面缺少业务行为 | 接入业务 API、结果回填与事件处理；预览和导出保留组件能力，不会生成实际后端服务 |
